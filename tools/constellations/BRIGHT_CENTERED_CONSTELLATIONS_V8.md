# Mellon v8 — brighter detected stars, unchanged centered geometry

**Status:** v8 code and independent validation added; full six-background library
is generated by the dedicated GitHub Actions workflow or with the command below.
The previous v6 matcher and `matches-v6.json` remain **unchanged**. M5.4 is
also untouched; this is offline preparation for M6 scene selection.

## What changed (and what did not)

| Area | v6 | v8 |
|---|---|---|
| Coordinates | Exact detected image-star IDs | **Unchanged** |
| Rigid template fit | Translation + rotation + uniform scale | **Unchanged** |
| Geometry acceptance | RMS ≤13 px, max vertex ≤24 px | **Unchanged** |
| Placement | Large, near center | **Unchanged** |
| Frame margin | 5% outer margin | **Unchanged** |
| Figure-art reserve | 9% on each side | **Unchanged** |
| Actual star safe region | 14%–86% screen bounds | **Unchanged** |
| Center deviation | ±13% horizontal/vertical | **Unchanged** |
| Min span | 55% of either screen dimension | **Unchanged** |
| Max template rotation | ±35° | **Unchanged** |
| Stars per constellation | Original template's exact vertex count | **Unchanged** |
| Cross-template collision checks | None; one constellation per lock | **Unchanged** |
| Bright-star preference | None | **Added, soft preference only** |
| GNOME lock-screen extension | M5.4 | **Unchanged** |

**Reminder:** “star” means a luminous point detected in the source photograph,
*not* a scientifically catalogued star with known magnitude or sky coordinates.
The source image is unchanged; catalog measurements come directly from the
original feature detector. No synthetic points are introduced.

### Brightness model

The full v3 catalog loader discarded `brightness` and `prominence`; v8
restores both by joining original detector metadata to the previously
transformed star coordinates **using source star IDs**, without re-detection.

Each source feature receives a per-background rank in [0, 1]:

```text
brightness_score = 0.75 × percentile(pixel_brightness)
                 + 0.25 × percentile(DoG_prominence)
```

`pixel_brightness` describes apparent pixel luminosity; `DoG_prominence`
measures local point contrast against surrounding nebulosity. A mostly
brightness-based score aligns with the desired visual effect while reducing
the chance that a bright diffuse region dominates a point-like star.

This score is used at three stages:

1. **Random-proposal shortlist**: the KD tree checks the nearest 8 real
   source points per projected template vertex. A source point may beat a
   closer dim neighbor when it is brighter; candidate shortlist scores
   reward average selected brightness by up to 5 pixel-score units.
2. **Unique star assignment**: the Hungarian assignment still enforces
   a **one-to-one** mapping of real source stars to template vertices.
   Its objective becomes `distance² + 8² × (1 - brightness_score)`
   in squared pixels. Brighter image points receive a bounded soft
   preference; they still must pass the original final geometry limits.
3. **Final ranking**: adds `0.08 × mean_brightness_score` to the original
   v6 merit score (size, geometric fit, rotation and centering remain in
   the merit calculation).

All three parameters are configurable. The hard acceptance checks are
**never** relaxed to accommodate brighter stars. As a result a brightness
winner can replace a lower-brightness placement only when the selected real
points remain within the unchanged geometric, central and illustration-safe
boundaries. Output remains `candidate-needs-visual-review`.

### Outputs

`matches-v8.json` uses schema
`mellon-bright-centered-constellation-matches-v8`. Each match retains
`star_ids`, `vertices`, `edges`, `coverage`, `center_offset_fraction`,
`figure_room_px`, `figure_envelope_bbox_px`, `rms_error_px`,
`max_error_px`, original `transform` and `rank_score`. New `brightness`
metadata contains per-star ranking, mean/min percentile, mean raw pixel
brightness, and mean local prominence. This makes QA and v6 comparison
straightforward.

## Full six-image / 31-template rebuild (BlackPearl, not the guest VM)

The command below matches the verified v6 search effort: **100,000
placements and up to 1,200 expensive refinements per image/template**,
`--limit 0` (no artificial output cap), and 3 previews per template.
No GNOME or VM files are modified.

```bash
(
    set -euo pipefail

    cd "$HOME/go/src/ap0calypse644/Mellon"
    git -c core.hooksPath=/dev/null pull --ff-only origin main

    PYTHON="$HOME/.local/share/mellon-constellations-venv/bin/python"
    OUTPUT="$HOME/VMs/Mellon/constellation-benchmark-v8-bright"
    V6="$HOME/VMs/Mellon/constellation-benchmark-v6-centered/matches-v6.json"

    "$PYTHON" tools/constellations/test_bright_v8.py

    "$PYTHON" tools/constellations/match_bright_centered_constellations_v8.py \
        --catalog all \
        --attempts 100000 \
        --refinements 1200 \
        --limit 0 \
        --min-span 0.55 \
        --frame-margin 0.05 \
        --figure-room-x 0.09 \
        --figure-room-y 0.09 \
        --center-tolerance-x 0.13 \
        --center-tolerance-y 0.13 \
        --rotation-limit-deg 35 \
        --qa-per-template 3 \
        --output "$OUTPUT"

    "$PYTHON" tools/constellations/verify_bright_centered_matches_v8.py \
        --report "$OUTPUT/matches-v8.json"

    if [[ -f "$V6" ]]; then
        "$PYTHON" tools/constellations/compare_brightness_v8.py \
            --v6 "$V6" \
            --v8 "$OUTPUT/matches-v8.json" \
            --output "$OUTPUT/brightness-comparison-v6-v8.json"
    fi

    echo "Library: $OUTPUT/matches-v8.json"
    echo "QA previews: $OUTPUT/<background>/qa/<constellation>/"
)
```

For a more intensive run, raise attempts/refinements as desired; all
geometric bounds, star coordinates, and safe margins stay unchanged.
Python requires `numpy`, `scipy`, and `Pillow` (already in the existing
Mellon venv).

## GitHub Actions: parallel brute-force reconstruction

The workflow `.github/workflows/bright-centered-v8.yml` provides:

- A fast **smoke job**: unit tests, two real images × three templates,
  independent v8 coordinate/brightness/center/art-margin verification.
- An explicit **full rebuild**: six independent image jobs, all 31
  constellation templates per image, original v6 100k/1200 search budget,
  independent post-search verification, and QA images.
- Six independently verified per-image artifacts in Actions, each
  named `bright-v8-<background>`. A separate strict merger
  (`merge_bright_v8.py`) combines the downloaded reports into a single
  library and rejects duplicate images, missing images or mismatched
  matching parameters. Run the independent validator on the result.

To repeat this on GitHub, open **Actions → Bright-star centered constellation
library v8 → Run workflow**, keep `rebuild_all` selected, and run it.

Artifacts have a 30-day retention in Actions. The workflow publishes
**six independent verified background reports** with QA previews. Once
the six jobs finish, you can download and combine them from BlackPearl:

```bash
(
    set -euo pipefail
    cd "$HOME/go/src/ap0calypse644/Mellon"
    OUTPUT="$HOME/VMs/Mellon/constellation-benchmark-v8-bright"
    mkdir -p "$OUTPUT/actions-parts"
    gh run download 42672244861 \
        --pattern 'bright-v8-*' \
        --dir "$OUTPUT/actions-parts"
    "$HOME/.local/share/mellon-constellations-venv/bin/python" \
        tools/constellations/merge_bright_v8.py \
        --parts "$OUTPUT"/actions-parts/bright-v8-*/matches-v8.json \
        --output "$OUTPUT/matches-v8.json"
    "$HOME/.local/share/mellon-constellations-venv/bin/python" \
        tools/constellations/verify_bright_centered_matches_v8.py \
        --report "$OUTPUT/matches-v8.json"
)
```

The resulting `matches-v8.json` is the input for M6 scene curation,
**not** a pre-approved scene set. If this Actions run fails, use the
self-contained local brute-force command above instead.

## Evaluate whether brightness genuinely improved

`compare_brightness_v8.py` loads the old full v6 report and the new v8
report, re-evaluates both top candidates for each common
background/constellation against the **same** original source feature IDs,
and reports average star-brightness percentile changes, number of
better/worse combinations, and per-combination geometry.

**It does not promise 100% improvements**: retaining the same size,
centering and rigid-fit preferences can legitimately keep a relatively dim
but better-shaped constellation above a brighter yet worse-shaped one.
Visual QA is still essential before choosing the 12–20 M6 scenes.

## Safety and versioning

- The full corpus is immutable input; catalog/photograph bytes are not edited.
- No GNOME extension or credential paths are touched by these offline tools.
