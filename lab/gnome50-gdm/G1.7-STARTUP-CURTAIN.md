# Mellon G1.7 — Eliminate the account-initialization logo flash

**Status: source + automated regression tests. Requires fresh VM smoke test.**
Previous validated G1.6B remains installed until a successful manual upgrade.

## Diagnosis

GNOME Shell 50 GDM's native `LoginDialog` owns a child
`_logoBin` and paints it over the existing Mellon background during
account-selection initialization. G1.6B mounted photo and HUD **below**
LoginDialog, then moved them **above** only after native user records
were loaded. During that gap, the Ubuntu logo briefly appeared.

G1.7 does **not** change GDM's logo setting, dconf database, PAM,
login layout, or system theme. Instead, the existing GDM extension
makes its verified astronomical background/HUD foreground immediately
after it mounts, including while the native roster is still loading.

**Limitation:** an extension cannot cover frames displayed *before
GNOME has enabled and mounted the extension itself*. An extremely
early boot splash could still appear. This version targets the
visible G1.6B account-initialization interval without global system
theme changes.

## Design

- **Startup curtain:** when the native `LoginDialog` exists but
  the user list isn't ready, Mellon's already-created photo,
  source-star actor, Observatory HUD and small
  `ESTABLISHING UPLINK` panel stack above native LoginDialog.
  The only interactive element is **SHOW LOGIN** at (26,22).
- **No new render timer:** the curtain reuses the existing bounded
  250ms GDM controller tick; it needs **zero independent timers**.
  Only the small status panel uses a 180ms fade-in; the photographic
  backdrop remains fully opaque, continuously, across handoff.
- **Single-user flow:** once the user roster stabilizes,
  G1.6B's native `UserListItem.activate` event begins the
  existing, visually validated G1.6A.1 constellation password
  screen. GNOME still handles all verification.
- **Multi-user flow:** existing G1.6B `SELECT OPERATOR` tiles
  replace the temporary `ESTABLISHING UPLINK` panel.
- **No stranded GDM:** after 32 controller ticks (~8 seconds)
  without a usable list, the curtain lowers every Mellon actor
  beneath native LoginDialog and returns native keyboard focus.
  SHOW LOGIN does the same immediately, permanently for that
  GDM dialog. Disabled user lists, oversized rosters, alternate
  authentication challenges and other unsupported structures
  fail open to the native screen. Unknown password challenges
  are never concealed.
- **Stable visuals:** the actual photo actor is never replaced
  during account/password handoff. The M8 photo stars, lines,
  completion lighting, five-second grid scan and mapping remain
  unchanged. Eight-stage mapping stays deferred. Mythology
  figures are still the final artwork feature.
- **Observer failure:** the GDM catch path now releases BOTH the
  account startup curtain and the password cover, ensuring
  native recovery is visible even if observer synchronization
  becomes unhealthy.

Only three installed system extension files change:
`extension.js`, `metadata.json`, and `greeter-account-chooser.js`.
The G1.6B styles and all scene assets are unchanged.

## Host preflight / stage (BlackPearl; no sudo)

```bash
(
    set -euo pipefail
    cd "$HOME/go/src/ap0calypse644/Mellon"
    git -c core.hooksPath=/dev/null pull --ff-only origin main
    bash lab/gnome50-gdm/stage-g17-to-vm.sh
)
```

Stage verifies the offline
`$HOME/VMs/Mellon/checkpoints/MELLON-GDM-PREINSTALL-001`
checkpoint manifest exists, verifies the isolated GNOME 50.1 VM,
checks currently installed G1.6B, runs legacy and new tests,
then copies three source files + two VM scripts + `SHA256SUMS` to:

`/home/test1/.local/state/mellon-gdm/g17-incoming-001`

The manifest is verified against the host hash. An existing
staging directory is **verified, never overwritten**.

## Install ONLY the isolated test VM after stage PASS and green CI

```bash
(
    set -euo pipefail
    ssh -tt mellon \
        'sudo bash /home/test1/.local/state/mellon-gdm/g17-incoming-001/install-g17-in-guest.sh'
)
```

The guest installer verifies GDM/GNOME 50.1, the immutable 12-scene
photo/sprite pack, G1.6B source signature, dconf profile, staged
SHA256 manifest and rollback viability before any swap.

An independent recovery helper is installed first at:

`/usr/local/sbin/mellon-greeter-g17-rollback`

The **entire** approved G1.6B greeter remains in:

`/usr/share/gnome-shell/extensions/.mellon-g17-previous-001`

The active extension is swapped by same-filesystem directory rename.
No GDM restart or host installation occurs automatically.

## Reboot only the VM after successful installation

```bash
(
    set -euo pipefail
    virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

### Required VM smoke checks

1. Watch first boot to the native GDM greeter. Mellon should show
   its photographic scene immediately when the GDM extension mounts,
   then its **ESTABLISHING UPLINK** panel briefly during account
   initialization. The Ubuntu logo should no longer flash during
   that covered interval. A pre-extension frame cannot be ruled out.
2. For VM account `test1`, account handoff should still select
   once, then show the normal full-screen constellation password
   interface without reset or background flash.
3. Verify random illumination, Backspace, connections, completion,
   5-second grid scan, incorrect-password UNAUTHORIZED ACCESS,
   and successful GNOME login.
4. Test SHOW LOGIN on the chooser and on the password prompt;
   both should reveal genuinely usable native GDM and focus.
5. Cancel back to user selection; only an explicit account tile
   can start authentication a second time (no auto-select loop).
6. Perform three login/logout cycles and change the VM display
   resolution if convenient; verify no duplicate HUD/actors.
7. Multiple-account tiles should remain available, but don't
   create VM users without explicit approval.

A synthetic GNOME test also verifies the 32-tick native fallback,
unknown OTP/username challenges, more than 8 users, account loading,
single-user handoff, multi-user tiles, no new timer, and rollback
guard for the REAL G1.6B dynamic HUD geometry.

## Emergency rollback (isolated VM only)

```bash
(
    set -euo pipefail
    ssh -tt mellon \
        'sudo /usr/local/sbin/mellon-greeter-g17-rollback'
    virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

Rollback moves G1.7 to
`.mellon-g17-failed-001` and restores the full G1.6B
extension from `.mellon-g17-previous-001`. The rollback
checks the **dynamic** G1.6B `hud-layout.js`, not the obsolete
static G1.5 layout (which previously made old rollback code fail).

**Never install Mellon GDM to the BlackPearl host without the user's
explicit approval.**
