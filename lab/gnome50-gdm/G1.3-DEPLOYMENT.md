# G1.3 — VM-only Observatory HUD deployment

**Prerequisites verified on 2026-11-12**

- G1.2.1 photograph is visible behind the native GDM user-selection
  and password prompt on Ubuntu 26.04.1 / GNOME 50.1.
- Existing 12-scene pack belongs to `mellon-greeter@local`, read-only,
  installed under `/usr/share/gnome-shell/extensions/`.
- The system greeter's `DCONF_PROFILE=gdm` is already correct.
- Verified offline checkpoint
  `$HOME/VMs/Mellon/checkpoints/MELLON-GDM-PREINSTALL-001`.
- BlackPearl's GNOME login and lock screen MUST stay untouched.

## G1.3 contents

Photo-only G1.2.1 becomes photo + four existing M8.3.2 HUD panels,
a clock, empty eight-segment mapping display and the original repeating
five-second grid. No GDM password, buffer length, verifier, or key
handling in G1.3. The user selector and password UI remain native GNOME.

The following **nine** files are updated or added:
`extension.js`, `metadata.json`, `hud-state.js`, `hud-layout.js`,
`hud-progress.js`, `hud-intro-state.js`, `observatory-hud.js`,
`observatory-intro.js`, `stylesheet.css`.

The preinstalled `scene-data.js`, all source photographs, photographic
star sprites, `library.json` and any original scene configuration remain
unchanged. GNOME Shell's extension system automatically loads the
top-level `stylesheet.css`.

## Step 1: validate and stage (host terminal, nonprivileged)

```bash
(
    set -euo pipefail
    cd "$HOME/go/src/ap0calypse644/Mellon"
    git -c core.hooksPath=/dev/null pull --ff-only origin main
    bash lab/gnome50-gdm/stage-g13-to-vm.sh
)
```

The script verifies the lock-scene artwork parity, syntax, tests,
offline checkpoint presence, the expected test VM, and host SHA256
checksums. It copies the nine code/style files plus **two installer and
rollback scripts** into guest user `test1` at
`/home/test1/.local/state/mellon-gdm/g13-incoming-001`.
The resulting 11-file bundle is verified inside the VM against the host
manifest. There is NO Node.js requirement in the VM.
If staging was interrupted, files are never blindly overwritten.
No root access, GDM settings or live extension is changed in this step.

## Step 2: replace extension ONLY inside the VM

```bash
(
    set -euo pipefail
    ssh -tt mellon \
      'sudo bash /home/test1/.local/state/mellon-gdm/g13-incoming-001/install-g13-in-guest.sh'
)
```

Enter the **test VM's `test1`** sudo password when prompted.
The updater verifies GDM 50.1, a virtual machine, the exact existing
G1.2.1 source signature, the GDM admin profile and keyfile, the
installed approved scene library, the 11-file staging manifest and all
required local files. It refuses unknown code or existing G1.3
installation attempts.

Recovery is installed **before** replacement at:
`/usr/local/sbin/mellon-greeter-g13-rollback`

The original G1.2.1 extension directory is preserved atomically at:
`/usr/share/gnome-shell/extensions/.mellon-g13-previous-001`

The new G1.3 extension directory is published by an on-filesystem
rename. GDM, dconf, PAM, vendor profiles and the `test1` user extension
are never edited by this step. It DOES NOT reboot or restart GDM.

## Step 3: test visual login after installation success only

```bash
(
    set -euo pipefail
    virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

Inspect the VM's actual native GDM user-selection screen and password
prompt. Verify all four HUD panels, top-right source constellation and
star count, real clock, initially unlit eight mapping segments, and
the five-second left-to-right cyan grid. Confirm native password entry
and successful login still work. Then lock the session to verify that
M8.3.2 remains unaffected, and log out to confirm G1.3 reappears.

**Visual result unverified until the user performs this test.**
If output/visuals are wrong, do not apply new fixes to a live greeter
blindly: collect scoped logs and use the rollback.

## Emergency rollback: root inside VM only

```bash
(
    set -euo pipefail
    ssh -tt mellon \
      'sudo /usr/local/sbin/mellon-greeter-g13-rollback'
    virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

The rollback verifies the exact old and current source signatures,
quarantines the failing G1.3 directory, and atomically restores the
visually approved G1.2.1 directory. No dconf update and no modification
to BlackPearl. The broader original G1 emergency uninstall remains at
`/usr/local/sbin/mellon-greeter-g1-rollback`. Offline VM checkpoint
remains an independent last-resort recovery mechanism.

## What G1.3 deliberately excludes

- No observing password length or attaching GDM callbacks.
- No dynamic star connections or ignition based on login input.
- No inferred successful authentication or false UI prompts.
- Mythological constellation artwork remains the last feature.
