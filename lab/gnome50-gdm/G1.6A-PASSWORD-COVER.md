# Mellon G1.6A — Lock-screen-matched GDM password cover

**Status:** source/CI implementation. Requires a TEST VM installation and
manual GNOME 50.1 validation. Working G1.5 remains in the VM until installed.

## Design
On the password screen, Mellon's photographed nebula, original star
sprites, constellation edges, M8.3.2 completion effects, and Observatory HUD
are drawn **above GNOME's native LoginDialog**, exactly as on the existing
M8 lock screen. The underlying password field retains focus and handles
all authentication. The only reactive Mellon UI is **SHOW LOGIN** at (26,22),
matching M8's one-way manual native-recovery control.

During initial user/account/session selection, the art stays **below**
LoginDialog, keeping the original account selector and accessibility
controls interactive. Username/OTP/unknown challenges remain fully native
and unobscured. A custom Mellon account selector is the distinct G1.6B stage.

A byte-identical M8 `FailureTracker` observes only the GNOME verifier's
read-only failed-attempt count. It never reads credentials. A failed attempt
clears visual stars and displays the red **UNAUTHORIZED ACCESS** alert for
1.5 seconds on a bounded timer. If the verifier is unknown, Mellon reveals
the native password UI instead. Entering the next password or pressing
SHOW LOGIN cancels the alert.

The GDM-only HUD geometry reserves the recovery button rectangle while
the password is covered. For user selection it retains the approved
four-panel G1.5 positions. All eight-stage mapping behavior is unchanged
(user deferred refinements). No mythological artwork is introduced.

**Changed installed files:**
`extension.js`, `metadata.json`, `greeter-password-cover.js`,
`failure-tracker.js`, `observatory-hud.js`, `hud-layout.js`.

## Stage on BlackPearl (no sudo)

```bash
(
  set -euo pipefail
  cd "$HOME/go/src/ap0calypse644/Mellon"
  git -c core.hooksPath=/dev/null pull --ff-only origin main
  bash lab/gnome50-gdm/stage-g16a-to-vm.sh
)
```

This runs regression tests, checks that the existing offline checkpoint
is present, verifies the known VM identity, and checks all six source
files + two scripts against a BlackPearl SHA256 manifest after copying
to `/home/test1/.local/state/mellon-gdm/g16a-incoming-001`. There is
NO Node.js requirement in the guest and NO GDM system writes in staging.

## Install ONLY in mellon-gnome50-lab after staging PASS and green CI

```bash
(
  set -euo pipefail
  ssh -tt mellon \
    'sudo bash /home/test1/.local/state/mellon-gdm/g16a-incoming-001/install-g16a-in-guest.sh'
)
```

The VM installer verifies approved G1.5 source, GNOME/GDM 50.1, curated
photo assets, unchanged dconf settings and exact staged SHA256 files.
It installs root-only recovery
`/usr/local/sbin/mellon-greeter-g16a-rollback`
BEFORE replacing the active extension. The entire verified G1.5
extension remains at
`/usr/share/gnome-shell/extensions/.mellon-g16a-previous-001`.
No GDM restart occurs automatically.

## Validate only after installer reports PASS

```bash
(
  set -euo pipefail
  virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

In the VM, confirm native user-selection works, choosing test1 opens the
full-screen astronomical PASSWORD view without visible avatar or native
password box, password typing still lights real stars, random Backspace
works, connections and completion are identical to M8, incorrect password
shows UNAUTHORIZED ACCESS, SHOW LOGIN reveals original GNOME login with
working focus, login and logout work, and password-mode reset restores the
cover. Test repeated cycles and safe display resizing.

## Emergency rollback (test VM only)

```bash
(
  set -euo pipefail
  ssh -tt mellon 'sudo /usr/local/sbin/mellon-greeter-g16a-rollback'
  virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

This restores entire G1.5 extension and quarantines G1.6A. Existing
offline `MELLON-GDM-PREINSTALL-001` disk/UEFI checkpoint is separate.
