# Mellon G1.6B — Astronomical GDM Account Selection

**Source stage only; live VM test remains required.**

## Goal

Boot into Mellon's astronomical scene instead of the stock GNOME
`test1` card. Preserve GNOME's existing authentication, session
selection, and accessibility behavior.

### Single eligible native account
Once GNOME 50's native user manager and user list are loaded, Mellon
shows a compact "IDENTIFYING OPERATOR" Observatory panel for approximately
1.25 seconds of a stable roster. It then emits the **same** native
`UserListItem.activate` event a physical GNOME account click would emit.
This selects the user and opens the G1.6A.1 custom astronomical PASSWORD
screen; it never types a password, calls PAM, or enables automatic login.

There is at most **one automatic activation per LoginDialog lifetime**.
If the user cancels the password screen and returns to account selection,
Mellon displays a single account tile that can be explicitly selected,
rather than repeatedly auto-launching authentication.

### Multiple eligible native accounts (2–8)
Mellon draws a centered translucent **SELECT OPERATOR** panel with
one clearly labeled, keyboard-focusable St.Button for each item in
the existing GNOME native `UserList._items` map. Clicking a tile emits
that exact item's `activate` signal; native GDM handles switching and
verification. No list items are fabricated and user names are not
written to logs.

### Native fallback / escape
**SHOW LOGIN** at (26,22) reveals the real native account list and
restores focus. When GDM's user list is not loaded, disabled, empty,
unexpected, has a timed-login hold, or has over eight eligible accounts,
Mellon leaves the native account chooser untouched. Unknown/alternate
auth challenges are still handled by the G1.6A.1 password cover's
existing safe native fallback.

Top-right GNOME session/accessibility controls, the password verifier,
dconf/PAM, and the native GNOME daemon are unchanged. The G1.6A.1
photo/HUD/starfield and 5-second grid sweep are reused; the eight-stage
mapping remains deferred. Mythological constellation drawings remain
the last feature.

## Safety and architecture

`greeter-account-chooser.js` reads the already loaded GNOME 50
`_userList._items` map. This Map is also the source used by GNOME's own
`UserList.getItemFromUserName` and account activation signal.
The controller observes only roster membership, no credentials.

The chooser is a non-reactive full-screen container with individual
reactive St.Button account tiles. A selected single/multiple user
hands control to `GreeterPasswordCover` so the existing
lock-screen-matched password visuals work unchanged.

The G1.6B package changes exactly four system extension files:

- `extension.js`
- `metadata.json`
- `greeter-account-chooser.js` (new)
- `stylesheet.css` (appended account tile styles)

**All G1.6A.1 photography, effects, intro animation, password cover and
authentication source files remain unchanged.**

## Stage on BlackPearl (read-only VM + guest-home copy)

```bash
(
    set -euo pipefail
    cd "$HOME/go/src/ap0calypse644/Mellon"
    git -c core.hooksPath=/dev/null pull --ff-only origin main
    bash lab/gnome50-gdm/stage-g16b-to-vm.sh
)
```

Staging verifies the existing offline VM checkpoint, GNOME 50.1,
G1.6A.1 installed as the current GDM extension, no previous G1.6B
rollback, Node regression tests, script syntax, and **identical SHA256
manifests** in host and VM. It copies four source files, two shell
scripts and a manifest only to:

`/home/test1/.local/state/mellon-gdm/g16b-incoming-001`

Staging does not modify GDM or reboot anything.

## VM-only installation

**Only after staging PASS and green GitHub Actions:**

```bash
(
    set -euo pipefail
    ssh -tt mellon \
        'sudo bash /home/test1/.local/state/mellon-gdm/g16b-incoming-001/install-g16b-in-guest.sh'
)
```

The installer verifies exact VM identity, original GDM 50.1,
curated scene assets, untouched dconf profile, and active G1.6A.1 marker.
It installs an independent emergency rollback *before* touching active
files, then keeps the entire approved G1.6A.1 directory at:

`/usr/share/gnome-shell/extensions/.mellon-g16b-previous-001`

The new extension is an atomic same-filesystem directory swap. No
daemon restart, password change, GNOME host extension changes, PAM edit,
or host GDM changes.

### Required manual VM checks

- On the first GDM screen with the one visible native account
  `test1`, the original GNOME account card should NOT appear after
  Mellon initializes. Mellon should automatically transition to the
  full-screen constellation PASSWORD view after approximately 1–2 seconds.
- Typing, random backspace, 5-second grid scan, completion, incorrect
  password **UNAUTHORIZED ACCESS**, SHOW LOGIN, and successful login
  should behave identically to G1.6A.1.
- Use the native back arrow, after SHOW LOGIN, to return to account
  selection. Mellon should show a *clickable* single-user tile instead
  of endlessly restarting the password prompt.
- Click SHOW LOGIN on the custom account chooser: native GDM account
  selection must reappear and remain keyboard/mouse accessible.
- Perform three complete login/logout cycles; ensure a fresh greeter
  still allows one automatic selection.
- Optional separate VM test: add a disposable second test user **only
  with explicit approval**, then verify exactly two native users have
  two custom choice tiles and neither is auto-selected. No need to
  mutate the VM's user database for the initial single-user smoke test.
- If a disabled/unsupported/oversized native roster is encountered,
  the original native list must remain accessible.

## Independent emergency rollback (VM only)

```bash
(
    set -euo pipefail
    ssh -tt mellon \
        'sudo /usr/local/sbin/mellon-greeter-g16b-rollback'
    virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

This restores the entire G1.6A.1 VM extension and quarantines G1.6B.
The independent `MELLON-GDM-PREINSTALL-001` offline checkpoint
is still untouched. **Do not install to BlackPearl host**.
