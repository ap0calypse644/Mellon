# G1.4 — Native-login constellation illumination (VM-only prototype)

## Status

G1.3.1 was visually verified in the GNOME 50.1 `mellon-gnome50-lab`
GDM user-selection and password views: all four Observatory panels and
photographic nebula render, and GNOME's original login controls remain
visible. This G1.4 implementation has **synthetic test coverage only**
until the below live VM deployment and screenshots pass.

## Implementation

- Greeter extension loads the exact original 12 curated nebula scenes,
  including each photograph and EVERY source-photo star sprite,
  before touching the GDM backdrop.
- `GreeterStarfield` creates an optional non-reactive sibling overlay
  of real source-photo stars between the photo and HUD, all **below**
  GNOME 50's original `LoginDialog`. Each scene uses the M8
  `coverTransform` for exact photo/star alignment and existing
  `StellarEffects` for ignition, random activation, authentic edges,
  completion bloom, and sustained bright mapped state.
- `GreeterLengthObserver` reads **only** `get_length()` from the
  active GNOME `AuthPrompt._passwordEntry`, never the text, keys or
  authentication result. It explicitly ignores username/other input,
  disconnects on prompt replacement, and sends only the scalar length
  to `GreeterStarfield`. The visual mapping inevitably makes an
  *approximate password-length threshold* observable on the greeter;
  this is a conscious decorative tradeoff and should remain
  disableable in any future production host deployment.
- A 250 ms read-only sync timer detects native prompt changes without
  replacing native credential handlers, and is disposed on disable.
- Existing G1.3.1 four HUD panels and recurring five-second scan remain
  unchanged; all star effects are non-interactive and visual-only.
- **No** GDM dconf, PAM, GNOME login dialogue internals, password text,
  input focus, or native auth code is modified.

Run from the BlackPearl terminal. Shell options are confined to a
subshell; Git hooks are disabled to protect the rebuilt workstation.

```bash

    git -c core.hooksPath=/dev/null pull --ff-only origin main
    bash lab/gnome50-gdm/stage-g14-to-vm.sh

```

The script runs current source, integration, runtime, guardrail and
syntax tests; confirms the full offline checkpoint exists; confirms
the known VM identity; and stages **five** G1.4 files (entrypoint,
metadata, two modules, and exact M8 `stellar-effects.js`) plus **two**
guest-only installer/rollback scripts. All seven are validated against
a host SHA256 manifest after copying into:

`/home/test1/.local/state/mellon-gdm/g14-incoming-001`

The VM intentionally does NOT need Node.js. Staging does not change
system GDM, service state, or BlackPearl. If a directory already
exists, it is verified in place without overwriting its contents.

## Step 2 — Install only in the TEST VM

**Only after staging passes:**

```bash
(
    set -euo pipefail
    ssh -tt mellon \
      'sudo bash /home/test1/.local/state/mellon-gdm/g14-incoming-001/install-g14-in-guest.sh'
)
```

The script verifies exact GNOME/GDM version, original G1.3.1 source
marker and its upper-left HUD geometry, approved 12-scene assets,
system-owned GDM config, checksum-verified new code and missing
old G1.4 backup state before making changes.

Before touching the active greeter, the emergency rollback is placed
at `/usr/local/sbin/mellon-greeter-g14-rollback`. The **entire**
working G1.3.1 extension is preserved in
`/usr/share/gnome-shell/extensions/.mellon-g14-previous-001`.
The changed module set is atomically installed by filesystem rename.

No GDM or VM reboot occurs automatically.
