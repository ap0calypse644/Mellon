# G1.5 — GDM Login Experience Stability and Transition Continuity

**Status: implemented and regression-tested in source. Live VM verification
is still required.** G1.4 is the current visually and functionally approved
test VM installation.

## Why G1.5

The G1.4 user-selection, native password prompt, photographic star
illumination, random backspace, connections, final glow, and correct and
incorrect authentication were validated in the test VM. The user
explicitly deferred changing the eight-stage visual mapping.

The G1.5 review identified three lifecycle failure modes:

1. GNOME 50 may destroy/recreate or temporarily detach its `LoginDialog`.
   The G1.4 250 ms read-only observer timer could then continue forever
   while polling for a replacement.
2. A recreated login dialog could cause `pickScene` to select a new
   photographic background in the middle of a single greeter session.
3. An exceptional read-only observer callback could leave its input
   synchronization timer running or surface an uncaught error to GNOME's
   main loop.

G1.5 fixes these **without modifying** the native login, dconf, PAM,
focus, user-lock extension, photographed sprites, star brightness,
scene geometry, original StellarEffects, Observatory HUD, five-second
grid or eight-stage mapping.

## Implementation

- A maximum of `GREETER_MAX_REBIND_TICKS = 120` recovery intervals
  bounds detached/replaced dialog reattachment to approximately
  **30 seconds** at `GREETER_LENGTH_SYNC_MS = 250`. At expiry Mellon
  removes its decorative actors and stops its timer, leaving native
  GDM usable.
- A scene selected at the start of a GDM session is reused when the
  native dialog is recreated. On a new extension enable, the choice
  resets, preserving randomized login/session starts.
- Observer failures are contained: disconnect the visual observer,
  clear the illuminated star mask, stop the 250 ms timer, and preserve
  photo + HUD + native login instead of allowing an uncaught exception.
  The warning is generic; no credentials, input counts or verification
  details are logged.
- The existing photo < original starfield < HUD < native LoginDialog
  actor order remains unchanged. No new input hook is added.
- The retired G1.4-only staging script refuses any future runtime
  version rather than accidentally installing a mismatched bundle.

### Automated tests

`test-g1-runtime.mjs` now covers repeated prompt polling,
LoginDialog loss/replacement and late return, stable nebula through a
dialog replacement, a permanently missing native dialog and bounded
timeout, simulated observer failure, actor cleanup, and all timers
removed on disable. Previous G1.4 effects, backspace, mapping and
VM-only deployment guardrail tests are retained.

**Testing limitations:** synthetic GNOME actors are mocks.
Actual GDM rendering, GObject lifetimes, authentication and visual
transitions need a VM smoke test; CI passing cannot establish that.


The updater confirms GNOME Shell 50.1, GDM 50.1, expected VM identity,

changed installed files are `extension.js` and `metadata.json`.

No GDM restart, dconf update, PAM edit or BlackPearl host login changes.

## Emergency rollback — guest-only

```bash
(
    set -euo pipefail
    ssh -tt mellon \
      'sudo /usr/local/sbin/mellon-greeter-g15-rollback'
    virsh -c qemu:///system reboot mellon-gnome50-lab
)
```

Rollback verifies the original G1.4 signature, quarantines the
G1.5 directory at `.mellon-g15-failed-001`, restores the entire G1.4
directory, and leaves the original GDM settings unchanged. The
separate MELLON-GDM-PREINSTALL-001 offline VM checkpoint remains the
last-resort recovery.
