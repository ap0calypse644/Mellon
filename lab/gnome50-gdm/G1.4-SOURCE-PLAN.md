# G1.4 — Dynamic photographed-constellation illumination

## Current status: source-only, NOT installed

The GDM greeter **G1.3.1 visually works** on Ubuntu 26.04.1/GNOME
50.1 in the `mellon-gnome50-lab` VM. Both native user-selection and
password screens retain the photographic nebula and all four HUD panels.
The recurring five-second grid still needs a direct live observation;
a static screenshot cannot confirm the cadence.

The G1.4 preparation adds only **new, unreferenced source files**
under `lab/gnome50-gdm/greeter-extension/`:

- `greeter-starfield.js`: reusable nonreactive `GreeterStarfield`.
  Consumes a numeric length and source-validated constellation geometry.
  Draws connecting edges only if **both real stars are active**.
  Reuses M8.3.2's exact `updateActiveStars`, `activeEdges`,
  `coverTransform`, and the approved `StellarEffects` envelopes.
  The bright sprites/halos re-display **original photographic pixels**;
  no synthetic nodes. Its rendering layer is a non-interactive
  GDM sibling to be mounted between the photo and HUD **below**
  GNOME's native `LoginDialog`.
- `stellar-effects.js`: byte-identical to approved M8.3.2.
- `greeter-length-observer.js`: independent `GreeterLengthObserver`.
  Checks `AuthPrompt._entry === AuthPrompt._passwordEntry`, that the
  password prompt is visible, and that we are in `gdm` session mode.
  Hooks only `ClutterTextBuffer.notify::length` and calls
  `buffer.get_length()`. It NEVER gets username or password strings,
  event keys, verifier state, or authentication results. It disconnects
  on prompt change and invalidates residual callbacks on teardown.

These were verified against upstream `gnome-50` source, including:

- `js/gdm/loginDialog.js`: `LoginDialog._authPrompt`.
- `js/gdm/authPrompt.js`: `AuthPrompt._passwordEntry` and active
  `AuthPrompt._entry`.
- `js/ui/screenShield.js`: `_lockDialogGroup`.

## Explicit deployment boundary

**The GDM extension entrypoint `extension.js` is unchanged.**
The new modules are not imported, copied into the VM, or invoked by
GDM. Existing G1.3.1 remains the working greeter. Never rerun the
old G1.3/G1.3.1 installer to get G1.4; those scripts only handle their
specific source packs.

Before G1.4 is deployable:

1. Expand synthetic renderer tests for graphic actor placement, visual
   fade, random-star activation, native LoginDialog stacking and cleanup.
2. Integrate observer and starfield in the GDM entrypoint, initializing
   the observer **only after all 12 assets pass validation** and actor
   layering is verified. Do not change the GDM prompt or focus.
3. Add a versioned, checksummed VM-only installer with a PREINSTALLED
   full G1.3.1 backup and emergency rollback. No Node requirement
   in the VM. No dconf/PAM/GDM changes.
4. Test user selection, native password prompt, typing, random
   backspace, wrong password, native login success, logout,
   multi-prompt/username flow, actor teardown, and full source-scene
   alignment in the VM before considering host deployment.

**Mythological constellation figures remain last.**
